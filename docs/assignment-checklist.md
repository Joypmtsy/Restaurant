## ฐานข้อมูลและเทคนิค

- ตารางธุรกิจ D1–D9 และ app_meta; มี FK มากกว่า 4 จุด พร้อม NOT NULL/CHECK/ON DELETE RESTRICT
- SQLiteProvider จุดเดียวใน src/app/_layout.js; ชื่อฐานข้อมูลเฉพาะโปรเจกต์ restaurant-order-01418342.db
- เปิด foreign_keys และ WAL ก่อน render หน้าจอ; ทุกการเขียนผ่าน queue/transaction บน connection เดิม เพื่อรักษา foreign_keys และป้องกัน write interleaving
- SQL อยู่ใน src/db; หน้าจอไม่เขียน SQL และไม่เปิดฐานข้อมูลเอง
- ค่า input ส่งผ่าน ?; ไม่มี `${` ใน db; ราคา INTEGER หน่วยสตางค์
- order_items.price_at_order เป็นราคาตอนสั่ง ไม่อ่านราคาปัจจุบันแทนราคาบิลเก่า
- ยอดบิลและยอดขายคำนวณด้วย SQL; ยอดในตะกร้าเป็นเพียงประมาณการก่อนส่งและยังไม่ใช่บิล
- Reset ลบ child tables ก่อน parent ภายใน transaction; คง master data และ marker ป้องกัน seed ซ้ำ
- ข้อมูลหลักอยู่ใน expo-sqlite ไม่มี ORM/AsyncStorage และไม่เรียกเครือข่ายระหว่างใช้งาน

## ผลทดสอบอัตโนมัติ

`npm test` ตรวจ end-to-end ของฐานข้อมูล: เปิดบิล, หลายรอบ, snapshot ราคา, เปลี่ยนสถานะ, ย้ายโต๊ะ, รับชำระ, รายงาน, reset, rollback ทั้งรอบเมื่อรายการใดผิด, concurrent writes, ข้อมูลอยู่หลังเปิดไฟล์ DB ใหม่, FK และ EXPLAIN QUERY PLAN

`npm run typecheck` และ `npm run lint` ตรวจทุกหน้า รายละเอียดผล runtime/อุปกรณ์ให้ตรวจจากสรุปงานล่าสุดด้วย ไม่ถือว่าการทดสอบฐานข้อมูลแทนการแตะ UI จริงบนทุกอุปกรณ์ได้
